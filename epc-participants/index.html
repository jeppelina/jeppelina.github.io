How this was built

By Jesper Lindmarker, Linköping University

This is a personal, unofficial tool built to make searching the participants and finding relevant connections easier. The method is described below so it is clear how the data was gathered. Nothing here is affiliated with EAPS or the EPC.

1. Source and scraping

The only input is the public conference programme at epc2026.eaps.nl. Each session page and each linked abstract page was downloaded once with a small Python script using only the standard library (urllib), at about one request per second, with on-disk caching so the site was read a single time. No login, no private data, no API.

2. Parsing

The saved HTML was parsed into structured records: people, their stated affiliation, their role (presenter, author, chair, discussant), the papers, the sessions, and the full abstract text. The totals are shown in the header.

3. Country

Country is not listed in the programme, so it is inferred from each person's affiliation string using a dictionary of institutions and place-name keywords. This is approximate: a few affiliations cannot be placed, and edge cases will be wrong.

4. "Who to meet" similarity

For each person a single document is formed from their paper titles and abstract text. Two similarity measures are computed between every pair of these documents and then averaged:

  • TF-IDF cosine. Term overlap weighted by how distinctive each term is. It rewards shared specific vocabulary (for example "assortative mating" or "register data").
  • Sentence-embedding cosine. Each document is encoded with the all-MiniLM-L6-v2 sentence-transformer (384 dimensions) and compared by cosine. This rewards topical closeness even when the wording differs.

The two scores are blended equally. People who share a paper are removed from each other's suggestions, since they already know each other, and the strongest matches per person are stored.

5. Building from your own interests

In the "Who to meet" tab you can also type free text. That text is turned into a TF-IDF vector in your browser, over the same vocabulary as above, and scored against everyone's stored abstract vector locally. It runs entirely on your device, so there is no model to download and nothing is sent anywhere.

If you set both an identity and some typed interests, the two stay separate rather than merging into one number: the deck alternates between cards picked by your typed interests and cards picked by similarity to your own abstracts, so neither one dominates the suggestions.

6. Programme

The "Programme" tab lists the parallel scientific sessions by day and time slot. It opens at the current time in Bologna (so during the conference you land on what is on now) and you can star sessions into your own agenda. Sessions that include anyone on your "who to meet" list are flagged, and those names are highlighted inside the session. Each session's theme comes from the programme's own topic listing, read once in the same way as everything else. Ceremonies, the welcome reception and other social events are not included.

7. Privacy and security

The whole dataset is encrypted with AES-256 (key derived with PBKDF2, SHA-256, 200,000 iterations) and is decrypted only in your browser with the shared password, through the built-in WebCrypto API. The page is fully static, with no server or database. Your chosen identity, typed interests, saved shortlist and starred sessions live only in this browser's local storage.
